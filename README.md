# Kuri Management Demo

A **fictional, educational demo website** for managing a "kuri" (chit fund) scheme,
built with **Django + SQLite** on the backend and **HTML/CSS/vanilla JavaScript
+ Chart.js** on the frontend. No React, Vue, or Node.js is used anywhere.

> ⚠️ **This is not an official KSFE website.** All member names, phone numbers,
> emails and payment records are randomly generated fake data for demo purposes only.

---

## 1. Features

- Django-authenticated login (`admin` / `admin123`)
- Dashboard with live stats (members, collections, pending amounts) + a Chart.js
  monthly collection chart
- Members: search, filter (active/inactive), sort, add / edit / delete / view
- Member Details: full profile + 40-month payment history + progress bar
- Payments: month & status filters, edit payment status/amount/dates in a modal
- **40-Month Tracking** grid: `Member × M1..M40`, click a cell to cycle its
  status via AJAX (saved straight to the SQLite database, no localStorage)
- Collection: month-by-month collected vs pending summary
- Notifications, Admin Profile (editable), Settings (scheme name/status/current month)
- All numbers on every page are computed live from the database — nothing is hardcoded

## 3. Setup & Run

Open the `kuri_demo` folder in **VS Code**, open a terminal (`` Ctrl+` ``), and run:

```bash
# 1. Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. Apply database migrations (creates db.sqlite3 and all tables)
python manage.py migrate

# 4. Seed demo data (1 kuri scheme, 20 fake members, 40 months of payments, admin user)
python manage.py seed_demo_data

# 5. Run the development server
python manage.py runserver
```

Then open **http://127.0.0.1:8000/** in your browser.

**Demo login:**
```
Username: admin
Password: admin123
```

The Django admin panel is also available at **http://127.0.0.1:8000/admin/** using
the same credentials, if you want to inspect/edit raw records.

## 4. Re-seeding data

`seed_demo_data` first clears existing members/payments/notifications and the kuri
scheme, then recreates everything fresh (the `admin` user and its profile are kept/
updated, not deleted). Safe to re-run any time:

```bash
python manage.py seed_demo_data
```

## 5. How the 40-Month Tracking grid works

Each cell in the tracking table has a `data-payment-id` and `data-status` attribute.
Clicking a cell (see `kuri/static/kuri/js/main.js`) sends a `fetch()` POST request
to `/payments/<id>/ajax-update/`, which is handled by `payment_ajax_update()` in
`kuri/views.py`. That view updates the `Payment` row in the SQLite database and
returns the new status plus the member's recalculated totals as JSON, which the
JS then uses to update the cell and the row's Paid/Pending/Progress columns —
so every change is persisted in the database, not just in the browser.

## 6. Notes

- `DEBUG = True` and a hardcoded `SECRET_KEY` are used for demo convenience only —
  never do this in a real production deployment.
- All monetary values, member details, and payment histories are fictional and
  generated by `seed_demo_data.py` using Python's `random` module with a fixed seed.
